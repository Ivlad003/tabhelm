# Cross-cutting themes for AI browser agents (as of 12 Oct 2026): safety & trust UX, UX patterns, business & distribution — with gaps for TabHelm

Scope: Claude in Chrome, OpenAI (Atlas → ChatGPT desktop browser mode + ChatGPT Chrome extension), Perplexity Comet, Gemini in Chrome (auto browse), Microsoft Edge (Copilot Mode → "Browse with Copilot"), Dia, Nanobrowser, BrowserOS, Browser Use, plus 2026 entrants (Opera Neon, Fellou, Browsergent). Labels used below: **[policy]** = documented in vendor help/security docs; **[vendor claim]** = vendor blog/marketing without independent verification; **[third-party]** = press, researchers, aggregators.

Note on sources: Several primary pages (openai.com, Zenity businesswire, Dark Reading) returned 403 to the fetcher; those facts are taken from secondary coverage and are marked. One aggregator page (ai-toolbox.co) mixes Claude-in-Chrome facts with its own product's stats (e.g. "40,000+ users, 4.7/5") — those product stats are ignored here.

## Key Question 1 — Safety & trust: documented prompt-injection defenses, action policies, visibility, 2026 incidents, industry guidance

### Takeaway
By October 2026 every major vendor documents the same four-layer stack — (a) a separate model/classifier that vets each action against the user's original intent, (b) instruction/data separation in prompts, (c) site-scoped permissions with blocked categories (finance/health/adult), and (d) hard confirmation gates before purchase/send/post/login/download — and every one of them was still publicly exploited in 2026 (ShadowPrompt, ClaudeBleed, PleaseFix). OWASP's 2026 Agentic Top 10 frames the goal as "least-agency + strong observability"; no vendor claims injection is solved, and Anthropic and OpenAI say so explicitly.

### Cited Findings

**Anthropic — Claude in Chrome**
- Red-team numbers [vendor claim, published]: 123 test cases / 29 attack scenarios; autonomous-mode attack success fell from 23.6% to 11.2% with mitigations; four browser-specific challenges (hidden form fields, URL/title injection) went from 35.7% to 0%. Defenses listed: site-level permissions, confirmation for "high-risk actions like publishing, purchasing, or sharing personal data", default blocks on "financial services, adult content, and pirated content", classifiers for "suspicious instruction patterns and unusual data access requests", improved system prompts. — [claude.com/blog/claude-for-chrome](https://claude.com/blog/claude-for-chrome)
- Rollout timeline: 1,000 Max users (Aug 2025) → all Max (24 Nov 2025) → Pro/Team/Enterprise with admin allowlists/blocklists (18 Dec 2025). — [claude.com/blog/claude-for-chrome](https://claude.com/blog/claude-for-chrome)
- Current permission model [policy]: side panel defaults to "Automatically approve" mode; Claude "reviews each action for safety, and pauses to ask you when something needs your approval"; preferences persist across sessions; admins can "restrict which websites Claude is allowed to access using allowlists and blocklists"; 1Password integration (macOS beta) so "1Password fills the credential directly so Claude never sees your password", each credential request approved by biometrics. — [support.claude.com getting started](https://support.claude.com/en/articles/12012173-getting-started-with-claude-in-chrome)
- Since 26 Aug 2026 (GA on all paid plans) auto-approval uses "the same mechanism as auto mode in Claude Code": a safety classifier checks each action against the original request; three modes exist (approve each action / auto-approve (default) / skip approvals). Items still needing explicit confirmation: entering sensitive information, granting authorizations or changing permissions, downloading files on "Always allow" sites. Prohibited: purchases, financial transactions, account creation, credit-card/ID handling, permanent deletion, following instructions found in emails/web content. — [ai-toolbox.co summary of Anthropic docs, third-party](https://www.ai-toolbox.co/claude-management-and-productivity/claude-for-chrome-setup-limits-2026). (The Claude Code auto-mode classifier study it draws on: in 1,053 paid testers, humans caught 13.6% of dangerous commands vs classifier 89% — [Banyan, third-party](https://www.banyanoutcomes.com/attention/2026-08-08-claude-code-auto-mode-default/).)
- Incidents 2026 [third-party]: **ShadowPrompt** (Mar 2026) — extension trusted any `*.claude.ai` origin for a prompt-carrying message path + DOM XSS in an Arkose CAPTCHA component on a-cdn.claude.ai → zero-click prompt injection; fixed in v1.0.41. — [The Hacker News](https://thehackernews.com/2026/03/claude-extension-flaw-enabled-zero.html), [Bastion](https://bastion.tech/blog/shadowprompt-claude-chrome-extension-vulnerability/). **ClaudeBleed** (reported May 2026, v1.0.69 → fixed v1.0.70 on 6 May 2026, researchers say bypass "is still six lines of JavaScript" in later versions): any other installed extension could inject prompts as if typed by the user and drive Gmail/Drive/GitHub; mainly affects "Act without asking" mode; recommended user mitigations: disable act-without-asking, audit extensions, keep AI off sensitive accounts. — [Malwarebytes](https://www.malwarebytes.com/blog/news/2026/07/claude-for-chrome-flaw-could-let-rogue-extensions-access-your-gmail). **PleaseFix** (Black Hat USA, 3–5 Aug 2026, Zenity Labs): zero-click chains across Claude in Chrome, Gemini in Chrome, Comet, Atlas, Copilot Edge; "Intent Collision" = hidden instructions interfere with the user's legitimate request; Claude chain "succeeded even in Claude's safe 'ask before acting' mode"; localhost access gave full machine control via dev tools (Ollama, Jupyter, pgAdmin) in Gemini/Edge/Comet; "HistoryFixing" planted false browser history; some vendors patched, others called it intended functionality. — [Zenity newsroom](https://zenity.io/company-overview/newsroom/company-news/zenity-labs-exposes-the-full-scope-of-pleasefix), [Dark Reading](https://www.darkreading.com/cyber-risk/ai-browsers-zero-click-agent-hijacking)
- CSA's six-risk model for Claude in Chrome (4 Sep 2026): indirect injection, identity inheritance, cross-origin authority, **approval fatigue & plan drift** (users flip to permissive mode under repeated prompts; agent navigates to unapproved domains mid-task; May 2026 disclosures showed approval states could be programmatically satisfied/DOM-rewritten), excessive capability (network-request reader surfaces OAuth tokens; JS execution in authenticated pages), inherited trust in vendor subdomains. Advice: "Govern it like a contractor with system access"; separate identities/profiles; agent-layer logging of every tool call, prompt, returned payload. — [Cloud Security Alliance](https://cloudsecurityalliance.org/blog/2026/09/04/top-6-claude-in-chrome-security-risks-to-model-before-you-roll-it-out)

**Google — Gemini in Chrome / auto browse**
- Architecture [policy, Dec 2025]: **User Alignment Critic** — a separate Gemini model "isolated from untrusted content" that "vets each action before it reaches the browser" (inspired by dual-LLM / CaMeL); **agent origin sets** (read-only vs read-writable origins per task); a visible **work log** with pause/stop; confirmation before navigating to banking/medical sites, signing in via Password Manager, purchases/payments/sending messages; a parallel prompt-injection classifier plus Safe Browsing; automated red-team sites; VRP bounty up to $20,000 for agentic boundary breaches. — [Google security blog](https://blog.google/security/architecting-security-for-agentic/)
- User-facing policy [policy]: AI Ultra 200 requests/day, AI Pro 20 requests/day; 18+ US, personal Google account, English, Safe Browsing on; user reviews an AI-generated plan then clicks "Start Task"; auto-browse icon on active tab; "Check your task" prompts; "Take over task" → "Resume"/"Give back task"; confirmation for "finalizing financial transactions, accepting terms of service, creating accounts … sending communications, modifying data, submitting web forms, scheduling events"; may decline/pause on "sites with highly sensitive financial or health data"; passwords via Password Manager, not shared with Gemini; payment and account creation "typically require manual completion"; agent activity appears in Chrome history with a Gemini icon. — [Google support: auto browse](https://support.google.com/chrome/answer/16821166)
- Enterprise policies: `GeminiActOnWebSettings`, `GeminiActOnWebAllowedForURLs`, `GeminiActOnWebBlockedForURLs`. — [Google Chrome Enterprise help](https://support.google.com/chrome/a/answer/16291696)
- Incident: CVE-2026-0628 (high) in Chrome's Gemini allowed local file access; patched. — [Sean Kim hands-on, third-party](https://blog.imseankim.com/chrome-auto-browse-gemini-agentic-hotel-form-fill-google-io-2026/); Unit 42 showed a malicious extension could hijack the Gemini side panel. — [Palo Alto Unit 42](https://unit42.paloaltonetworks.com/gemini-live-in-chrome-hijacking/)

**OpenAI — Atlas → ChatGPT desktop browser mode**
- Atlas agent mode [policy, via secondary]: paused on sensitive sites such as banks; could run "logged-out mode without your cookies"; cursor control with UI highlighted in blue. Atlas shut down 9 Aug 2026; agent actions now live in the ChatGPT desktop app (built-in browser, "Work and Codex use the built-in browser"); the new ChatGPT Chrome extension is "primarily a read-and-assist tool", with tasks started from the desktop app via `@Chrome`. — [Wikipedia: ChatGPT Atlas](https://en.wikipedia.org/wiki/ChatGPT_Atlas), [ai-toolbox Atlas guide](https://www.ai-toolbox.co/chatgpt-management-and-productivity/chatgpt-atlas-browser-guide-2026), [TechCrunch 9 Jul 2026](https://techcrunch.com/2026/07/09/openai-is-shutting-down-atlas-but-its-ai-browser-ambitions-are-still-growing/)
- OpenAI statement (30 Dec 2025): "Prompt injection is one of the most significant risks we actively defend against"; shipped an adversarially trained model plus LLM-driven RL automated attacker; no public attack-rate numbers. — [CyberScoop](https://cyberscoop.com/openai-chatgpt-atlas-prompt-injection-browser-agent-security-update-head-of-preparedness/). Feb 2026: OpenAI said injection "may never be fully patched". — [ai-browser-comparison-2026 (GitHub, third-party)](https://github.com/rishabhsaini282/ai-browser-comparison-2026)
- LayerX "Tainted Memories" — malicious sites injected instructions into ChatGPT memory. — [Wikipedia: ChatGPT Atlas](https://en.wikipedia.org/wiki/ChatGPT_Atlas)

**Perplexity — Comet**
- Brave's disclosure (July–Aug 2025): Comet put whole page text into the prompt with no instruction/data distinction; Reddit spoiler-tag comment stole OTP/email. Brave's four design recommendations: (1) segregate user instructions from page content, (2) independently verify actions against the user's objective, (3) explicit confirmation for sensitive operations (email, financial), (4) isolate agentic mode from normal browsing. — [Brave blog](https://brave.com/blog/comet-prompt-injection/)
- Perplexity's answer (22 Oct 2025) [vendor claim]: parallel ML classifiers for hidden HTML/CSS, image-based injection, goal hijacking; external content marked "untrusted"; intent reinforcement; confirmations for emails, calendar changes, orders, unknown user details; transparent notifications when a block fires; no numbers, no sandboxing or blocked domains mentioned. — [Perplexity blog](https://www.perplexity.ai/hub/blog/mitigating-prompt-injection-in-comet)
- Permission model [policy]: three levels — browse yourself / give permission once / auto-browse; sidecar shows reasoning + "clear buttons to stop the Assistant or provide more guidance"; pauses for logins and purchase completion. — [Perplexity blog, Nov 2025](https://www.perplexity.ai/hub/blog/comet-assistant-puts-you-in-control). Enterprise admins: per-domain "Browser Control / Read Only / No Access", option to disable "Always Allow" so every action prompts; domain settings override global. — [Perplexity help: managing permissions](https://www.perplexity.ai/help-center/en/articles/13531023-managing-comet-assistant-permissions)
- Comet Enterprise (17 Mar 2026): "let Comet answer questions without taking actions… or permit actions only on approved domains"; silent MDM installer; telemetry and audit logs per user; CrowdStrike Falcon integration; blocks suspicious files/links; prevents sharing via screenshots/downloads. — [Perplexity blog](https://www.perplexity.ai/hub/blog/comet-enterprise-is-here)

**Microsoft — Edge**
- 13 May 2026: "we're retiring Copilot Mode"; Copilot Actions → "Browse with Copilot", Microsoft 365 Premium subscribers, US only, "usage limits apply"; long-term memory; Journeys. No safety mechanics documented in that post. — [Microsoft Edge blog](https://blogs.windows.com/msedgedev/2026/05/13/new-updates-to-edge-across-desktop-and-mobile/)

**Open-source tools**
- Browser Use README does not discuss sensitive-data handling, `allowed_domains`, or human-in-the-loop (these exist in the Python API but aren't README-documented); cloud sells stealth browsers/proxies "designed to reduce bot detection and CAPTCHA challenges". — [GitHub browser-use](https://github.com/browser-use/browser-use)
- BrowserOS: data local under `~/.browserclaw/`; session replay with video scrubbing + action timeline; anonymous telemetry; browser ACLs ("role(agent): can never click buy") were "in early development" per HN. — [GitHub BrowserOS](https://github.com/browseros-ai/BrowserOS), [Show HN](https://news.ycombinator.com/item?id=46721474)
- Browsergent (2026 side-panel entrant): agent "never touches the DOM or Chrome APIs directly — it only writes JavaScript" run in a sandbox; README warns it can read cookies/auth headers and to avoid sensitive accounts. — [GitHub Browsergent](https://github.com/Irvingouj/Browsergent)
- Nanobrowser: safety story is "everything runs in your local browser"; no documented confirmation gates. — [GitHub nanobrowser](https://github.com/nanobrowser/nanobrowser)

**Industry guidance**
- OWASP Top 10 for Agentic Applications 2026 (published 9 Dec 2025, 100+ contributors): ASI01 Goal Hijack, ASI02 Tool Misuse, ASI03 Identity & Privilege Abuse, ASI04 Supply Chain, ASI05 Unexpected Code Execution, ASI06 Memory & Context Poisoning, ASI07 Insecure Inter-Agent Comms, ASI08 Cascading Failures, ASI09 Human-Agent Trust Exploitation, ASI10 Rogue Agents. Principles: "Least-Agency" and "Strong Observability"; ASI09 mitigation = "critical human review (not rubber-stamp approval); agent must articulate reasoning, data sources, and intended tools"; ASI08 = pause and seek human on errors, transactional rollback; ASI10 = auditable kill-switch. — [NeuralTrust summary](https://neuraltrust.ai/blog/owasp-top-10-for-agentic-applications-2026), [Cycode summary](https://cycode.com/blog/owasp-top-10-agentic-applications/)
- CISO checklist from a May-2026 comparison repo: audit shadow installs, disable persistent memory by policy, require "Lockdown Mode" (explicit confirmation for file/account access), map data sovereignty, update DLP, deploy browser isolation. — [GitHub ai-browser-comparison-2026](https://github.com/rishabhsaini282/ai-browser-comparison-2026)

### Inferences
- The industry consensus "dual-model" pattern (Google's User Alignment Critic, Anthropic's auto-mode classifier, Perplexity's parallel classifier) is cheap to approximate in TabHelm: a second, page-content-free LLM call that sees only {user task, proposed action, target URL} and vetoes mismatches. This is the single most-cited defense and TabHelm has none.
- Google's "agent origin set" (declare read-only vs writable origins per task, block navigation outside) is the most concrete answer to CSA's "plan drift" — TabHelm's "always confirm for a tab the user didn't share" is a weaker cousin; a per-task origin allowlist with a visible "left the allowed set" prompt would match it.
- Two 2026 incidents (ShadowPrompt, ClaudeBleed) were about *who can send a prompt to the extension*, not the model. TabHelm should verify that its side panel only accepts commands from its own UI/native host (no `externally_connectable`, no `window.postMessage` prompt path, sender checks on `chrome.runtime.onMessage`).
- PleaseFix shows "ask before acting" alone does not stop data exfiltration via reads (summarize email → leak). Confirmation gates must cover *outbound data* (navigating to a URL containing page-derived data, form submissions carrying page data), not just clicks.
- Every vendor blocks or pauses on finance/health/adult by category; Google additionally pauses on localhost-style dev tools after PleaseFix. TabHelm has no category list at all.

### Gaps
- No independent, like-for-like attack-success-rate comparison across products in 2026 was found; only Anthropic publishes numbers (23.6→11.2%), and those are from 2025.
- Could not fetch OpenAI's own Atlas/ChatGPT safety pages (403); agent-mode safeguards post-Atlas are reported only second-hand.
- Microsoft publishes no prompt-injection defense details for "Browse with Copilot"; Dia publishes none (its agentic scope is minimal).
- Zenity's per-vendor patch status for PleaseFix is not itemised in accessible sources.

## Key Question 2 — UX patterns reviewers praise or criticize

### Takeaway
Praised in 2026: working inside the user's existing logged-in browser, a visible plan-then-run step, real-time cursor/glow plus a step log, "take over / give back" hand-offs for 2FA and payments, background execution with notifications, reusable shortcuts/skills and scheduled tasks. Criticized: speed (slower than manual), usage-quota burn, approval fatigue, weak model tiers on cheaper plans, forced UI (Gemini pane), and agents that stall on unlabeled buttons or confirmation modals.

### Cited Findings
- **Onboarding/site access**: Claude in Chrome — site-level grants, allow/always allow/decline per action, admin allow/blocklists; 1Password handoff for logins. — [support.claude.com](https://support.claude.com/en/articles/12012173-getting-started-with-claude-in-chrome). Comet — one-time vs always allow; per-domain Browser Control/Read Only/No Access. — [Perplexity help](https://www.perplexity.ai/help-center/en/articles/13531023-managing-comet-assistant-permissions). Gemini — Password Manager fills logins with permission; user reviews a plan before "Start Task". — [Google support](https://support.google.com/chrome/answer/16821166)
- **Progress UI**: Gemini — auto-browse icon on the working tab, "Switch tabs", "Check your task", work log. — [Google support](https://support.google.com/chrome/answer/16821166), [Google security blog](https://blog.google/security/architecting-security-for-agentic/). Comet — sidecar with reasoning steps, visible clicks/scrolls, stop/guide buttons. — [Perplexity blog](https://www.perplexity.ai/hub/blog/comet-assistant-puts-you-in-control). Atlas — blue-highlighted UI during agent control. — [Wikipedia](https://en.wikipedia.org/wiki/ChatGPT_Atlas). Claude — reviewer liked that "the edges of the screen had a nice glow… indicating that Claude was at work". — [XDA](https://www.xda-developers.com/claude-chrome-extension-regret/). BrowserOS — session replay with video scrubbing + action timeline, live dashboard for parallel agents. — [GitHub BrowserOS](https://github.com/browseros-ai/BrowserOS). Browsergent — per-step trace view with code inspection. — [GitHub](https://github.com/Irvingouj/Browsergent)
- **Interruptibility / hand-back**: Gemini "Take over task" → "Resume"/"Give back task"; pauses at MFA; a hands-on reviewer praised "pause-and-resume across 2FA prompts" and "hard stops before financial commitments", but auto browse "refused — politely — to actually click 'Place Order'" and failed on subscription-cancellation modals and unlabeled buttons. — [Sean Kim hands-on](https://blog.imseankim.com/chrome-auto-browse-gemini-agentic-hotel-form-fill-google-io-2026/), [Google support](https://support.google.com/chrome/answer/16821166)
- **Background tasks & notifications**: Claude — "Background workflows continue while browsing other tabs"; scheduled recurring tasks (daily/weekly/monthly/annually) via clock icon; shortcuts via "/" command; built-in navigation knowledge for Slack, Google Calendar, Gmail, Docs, GitHub. — [support.claude.com](https://support.claude.com/en/articles/12012173-getting-started-with-claude-in-chrome). Since 12 Aug 2026 the side panel is a Claude Cowork session with saved conversations, skills, plugins, connectors. — [ai-toolbox](https://www.ai-toolbox.co/claude-management-and-productivity/claude-for-chrome-setup-limits-2026). Gemini — notifications when attention needed. — [Google support](https://support.google.com/chrome/answer/16821166)
- **Memory/personalization**: Edge adds long-term memory referencing past chats and multi-tab reasoning. — [Edge blog](https://blogs.windows.com/msedgedev/2026/05/13/new-updates-to-edge-across-desktop-and-mobile/). Atlas memories were a criticized privacy surface (Tainted Memories). — [Wikipedia](https://en.wikipedia.org/wiki/ChatGPT_Atlas). Gemini connects Gmail/Calendar/Maps/YouTube with opt-in. — [WindowsForum, third-party](https://windowsforum.com/threads/chrome-gemini-brings-agentic-browsing-with-auto-browse-and-connected-apps.399330/)
- **Mobile/companion**: Comet is free on iOS, Android, Windows, Mac since 18 Mar 2026. — [CloudZero, third-party](https://www.cloudzero.com/blog/perplexity-pricing/). Gemini auto browse rolled to Android per hands-on but Google's help page says desktop only (conflict; treat as in flux). — [Sean Kim](https://blog.imseankim.com/chrome-auto-browse-gemini-agentic-hotel-form-fill-google-io-2026/) vs [Google support](https://support.google.com/chrome/answer/16821166). Claude in Chrome: "Google Chrome only (not other Chromium browsers or mobile)". — [support.claude.com](https://support.claude.com/en/articles/12012173-getting-started-with-claude-in-chrome)
- **Multi-language**: XDA reviewer used Claude's sidebar in English, Spanish, Italian to read sites in languages she doesn't speak. — [XDA](https://www.xda-developers.com/claude-chrome-extension-regret/). Gemini auto browse requires English Chrome. — [Google support](https://support.google.com/chrome/answer/16821166). Edge Journeys desktop in en-US/GB/CA/AU/NZ/IN/SG only. — [Edge blog](https://blogs.windows.com/msedgedev/2026/05/13/new-updates-to-edge-across-desktop-and-mobile/)
- **Criticism of Claude in Chrome** [third-party]: "noticeably slower than doing things manually" (30 min–2 h workflows); Pro users "stuck with Haiku 4.5"; "eats through your usage limits much faster than regular chat"; "not production-ready for all workflows"; "permission anxiety"; praise for multi-tab workflows, Cowork/Claude Code integration, and being "more transparent about risks than its competitors". — [AI Tool Analysis review](https://aitoolanalysis.com/claude-in-chrome-review/). Screenshot tool "captured the entire screen rather than the section I selected". — [XDA](https://www.xda-developers.com/claude-chrome-extension-regret/)
- **Criticism of Gemini**: The Register: Google will "foist" the pane on users; auto browse paywalled; sites push back legally (Amazon v. Perplexity, eBay human-review terms). — [The Register](https://www.theregister.com/2026/01/29/chrome_gemini_pane/)
- **Criticism of Dia**: "automation stops at chat and text generation… Booking flights, updating CRMs… remain manual"; scrapes visible text but can't read links/structure; praised for stability. Skills = "pre-built shortcuts". — [Composite review](https://composite.com/blog/dia-browser-reviews-pricing-alternatives)
- **Approval fatigue** named as a top risk: users switch to permissive mode under repeated prompts. — [CSA](https://cloudsecurityalliance.org/blog/2026/09/04/top-6-claude-in-chrome-security-risks-to-model-before-you-roll-it-out)
- **What HN users ask open-source agents for**: headless/server mode, workflow marketplace, MCP integrations (Twilio, Square, email), scheduled automation; critics asked why a Chromium fork vs an extension. — [Show HN BrowserOS](https://news.ycombinator.com/item?id=46721474)

### Inferences
- "Plan → confirm → run" (Gemini) is a cheap replacement for per-action prompts and directly addresses approval fatigue: TabHelm could show a 3–6 line plan with the target domains and only interrupt on deviations/sensitive gates.
- "Take over / give back" is now expected for logins, 2FA, CAPTCHAs and payments across Gemini, Comet, Claude; TabHelm's hard "always confirm" gates should become an explicit "hand me the tab" state with a resume button.
- Visible per-tab badge/glow during a run is universal; TabHelm has the cursor but reviewers also reward a tab-level indicator and a completion notification when the task ran in a background tab.
- Shortcuts/skills triggered by "/" and scheduled recurring runs are now table-stakes in Claude and BrowserOS roadmaps; TabHelm's "skills from links" is close but lacks a "/" picker and scheduling.

### Gaps
- No Sept–Oct 2026 Verge/Wired/Ars review of these agents surfaced in search; UX criticism is drawn from XDA, The Register, specialist blogs and hands-on posts.
- No published keyboard-shortcut or omnibox documentation found for Claude in Chrome / Comet beyond the "/" shortcut picker.
- No data on how notifications for finished background tasks are delivered (OS-level vs in-panel) for any product.

## Key Question 3 — Business models, distribution, community, docs

### Takeaway
Consumer browser agents split into "bundled with a $20/mo AI subscription" (Claude Pro/Max, Google AI Pro $19.99 / Ultra $249.99, ChatGPT Plus, Dia Pro $20, Opera Neon $19.90, M365 Premium) and "free to drive distribution" (Comet since Mar 2026, Nanobrowser, BrowserOS, Browser Use OSS); open-source projects monetise via cloud browsers (Browser Use: $0.02/browser-hour, $29–$999/mo plans), enterprise licences (BrowserOS, AGPL) or nothing (Nanobrowser, Apache-2.0). Chrome Web Store listing is the primary consumer channel — Claude's extension shows 11–18M users but only ~2.7–2.9★ (paywall confusion), Nanobrowser ~50K users at 3.9★.

### Cited Findings
- **Claude in Chrome**: Pro/Max/Team/Enterprise only; Chrome only. — [support.claude.com](https://support.claude.com/en/articles/12012173-getting-started-with-claude-in-chrome). ### Inferences

## Key Question 4 — Explicit gaps and differentiators for TabHelm

### Takeaway
Against 2026 norms TabHelm lacks: a second-model action critic, per-task origin sets/category blocklist, a plan-preview step, take-over/give-back hand-off, tab badge + completion notifications, scheduled tasks, "/" shortcuts, memory, Windows, Web Store listing, mobile, and an enterprise policy surface. It keeps real differentiators: local-first with no account, BYO CLI agent, free and MIT, video recording + cost stats that most competitors don't expose.

### Cited Findings (what is table-stakes, with source)
- Classifier/critic on every action — Anthropic (auto mode, 26 Aug 2026), Google (User Alignment Critic), Perplexity (parallel classifiers). — [ai-toolbox](https://www.ai-toolbox.co/claude-management-and-productivity/claude-for-chrome-setup-limits-2026), [Google security blog](https://blog.google/security/architecting-security-for-agentic/), [Perplexity blog](https://www.perplexity.ai/hub/blog/mitigating-prompt-injection-in-comet)

### Inferences — concrete adoptable practices for TabHelm (ordered by cost/benefit)
1. **Action critic**: before executing any click/type/navigate, send {task, action, URL, short DOM label} to a second call that has never seen page content; veto on mismatch; log the verdict in the steps block. Mirrors Google/Anthropic/Perplexity.
2. **Per-task origin set**: infer or ask for allowed domains at task start (read-only vs writable); prompt once if the agent wants to leave the set. Replace "always confirm for tabs the user didn't share" with this.
3. **Category blocklist** shipped as a JSON file (banking, brokerage, crypto, health portals, adult, gov ID, localhost/dev tools) → pause, never auto-approve; user-editable.
4. **Sensitive-action gate list** made explicit and visible in settings: purchase/payment, send/post, accept ToS, create account, delete, download, login, form submit carrying page-derived data. Today TabHelm gates uploads/JS/unshared tabs only.
5. **Plan preview** (3–6 bullet plan + domains) before the first action; auto-approve mode then only interrupts on gates/deviations — direct answer to approval fatigue.
6. **Take over / give back** state for logins, 2FA, CAPTCHA, payment: pause the agent, hide cursor, show "Resume" button; never attempt CAPTCHAs.
7. **Tab badge + OS notification** on completion/attention-needed; mark agent navigations in history (or in TabHelm's own log) with a marker.
8. **Message-path hardening**: reject prompts not originating from the side panel/native host; no `externally_connectable`; sender checks; document this in README (vendors got burned by exactly this).
9. **"/" shortcuts + scheduled tasks** on top of existing skills-from-links; scheduling can run via the CLI agent's own cron (local-first).
10. **Windows support** and a **Chrome Web Store listing** (even if the native host still needs the installer) — reviewers consistently list Windows and Store install as baseline; competitor ratings show the listing itself won't fix satisfaction, but unpacked-only install limits reach.
11. **Policy file for teams**: allowlist/blocklist, answer-only mode, "always-approve disabled", export of action log — matches Comet/Gemini admin controls without a cloud.
12. **Keep and market the differentiators**: no account, no cloud, BYO CLI agent (Claude Code / Codex), video + cost/token stats (none of Claude/Gemini/Comet show per-task cost), MIT licence.

### Gaps
- No reviewer explicitly evaluated an "unpacked extension + installer" distribution model, so the cost of not being on the Web Store is inferred, not measured.
- Undo/rollback: no product documents an undo for agent actions; OWASP ASI08 recommends transactional rollback but no browser agent implements it visibly — opportunity, not a documented practice.
- Rate/action limits: only Google publishes hard per-day request caps (20/200); no vendor documents per-task action-count limits.
